# AGENTS.md -- `src/pers`

## 职能

把表写进介质,再从介质读回来.

- `mod.rs` -- [`Persister`](mod.rs) 抽象;`TablePath { data, schema }` 记住一对文件.
- `heap.rs` -- [`HeapTab`](heap.rs) / [`BufferPool`](heap.rs):基表格式之一(页式堆
  文件 + 缓冲池,TODO 7.5).数据在磁盘上,按行号随机访问,写只追加.
- `csv.rs` -- [`CsvPersister`](csv.rs):基表格式之一(标准 CSV + 旁路 JSON).数据整份
  读进内存,整表重写出去,换来"文件别的工具直接读".

**两种基表格式是并列的**,由 [`Storage`](mod.rs) 选(会话级,见 `usr/AGENTS.md` 的
"存储模式"):一张表用哪一种记在提交记录里,同一个库可以两种并存.

**这一层只依赖 [`Table`](../db/table.rs) 抽象**:`save` 吃的是 `&dyn Table`,所以
连接表等虚表的结果也能直接落盘.**不要往下假设它是 `PhysTab`.** 反过来,"我自己
落盘"的表通过 [`Table::paged`](../db/table.rs) 那条可选口子把位置交给提交点
(见 [`Paged`](../db/table.rs))--堆表就是这么免掉整表重写的.

## 磁盘布局

```text
<dir>/<name>.heap               基表:记录流 [len u32][rid u32][行编码](只追加)
<dir>/<name>.log                行位置日志:挪过窝的行在这里改地址(16 字节一条)
<dir>/<name>.schema.json        模式:{version, name, columns:[{name, ty}]}
<dir>/<name>.heap.new           暂存:即将成为 `<name>.heap` 的那一份(整理/迁移用)
<dir>/<name>.csv                老格式的基表:只在**迁移**时读一次,之后删掉
<dir>/<name>.csv.new            暂存:老格式的兜底路径用
<dir>/<name>.schema.json.new    暂存:与上面成对
```

`<name>.heap` 里的**行编码**逐列是 `tag u8`(0 = NULL,1 = 有值)+ `u32 长度` +
该值的 **CSV 字段文本**:字段口径与老数据文件**完全相同**(NULL 是 `\N`,以 `\`
开头的文本多写一个 `\`),于是"值怎么落盘"只有一处说法.

它**不自带**"到哪儿算数"的账本--那是库目录里的 `manifest.json`(见
`usr/AGENTS.md`):文件里多出来的字节(崩在半路的写,回滚掉的行)打开库时截掉.

## 页式堆表(`heap.rs`)

**基表不再常驻内存**:数据全在 `<表>.heap` 里,读的时候按 **8 KiB 页**取
([`BufferPool`](heap.rs) 按预算缓存,满了按 LRU 淘汰),`row(r)` 先查**行目录**
(内存里,每行 12 字节:页 / 页内偏移 / 长度,打开时**只扫记录头**建出来)再去池里
取那一段.

- **写只追加**:`INSERT` / `UPDATE` / 回滚的截断都只在文件尾写(或者什么都不写),
  而"写到哪儿算数"记在提交记录里.于是**没有 WAL 也能拿到原子性**:一条记录要么落在
  已提交长度之内(算数),要么落在外(打开库时截掉),没有第三种.
- **`UPDATE` 不原地改**:行变长了就得挪位置,而"原地改一半"就是改了一半的库.旧版本
  留在文件里变成**死字节**,整理时消失.
- **行的地址**:`rid` 在已提交范围之内的行,地址改了要写进 `<表>.log`(**行位置
  日志**,16 字节一条:`[rid][page][offset][len]`);`rid` 更大的那些行地址只在内存里
  (`<库>/manifest.json` 里的行数之外本来就不算数).日志同样是追加式的,**条数**记在
  提交记录里.
- **整理**:文件里的死字节比活着的多一倍以上(而且文件够大)就**在打开库时**按当前
  行目录密集重写一遍(`write_dense` -> 清单记新位置 -> `promote`).选在打开时是因为
  那一刻**没人拿着这份文件读写**;提交途中换掉正在写的文件会让文件句柄指错地方.
- **迁移**:打开库时见到的老格式(CSV 基表)在
  [`Database::recover`](../usr/service.rs) 里整表搬进来:写 `<表>.heap.new` -> 清单
  记位置(提交点)-> `promote` -> 删掉 CSV.
- **一条记录可以跨页**:页只是**缓存**的单位,不是布局的单位(所以没有槽数组).

把类型放在旁路文件里,是为了让数据文件保持**标准 CSV**(别的工具能直接读).
"一个目录 = 一个库"这个约定现在有人用了:[`usr::service`](../usr/service.rs) 把
服务目录下的一个子目录当库(`<库>/catalog.json` 记 owner 等元数据),表文件仍然走
`TablePath`.**库级元数据不归这一层**--`catalog.json` 的格式在 `usr/service.rs`.

## 特殊规则

### 落盘分两步:暂存 + 推广(整表重写那条路)

- `stage` 把两份文件写成暂存名(**直接写**,不必先 `.tmp` 再改名:暂存名没有任何读者,
  写坏了由恢复清扫);`promote` 再把它们 `rename` 到正式位置(各一次,同文件系统内原子).
- **单表提交就是"暂存 + 立刻推广"**(`Persister::save`);多表提交由 `usr::service`
  把所有表都暂存完,写下提交记录之后才一起推广--这是多表提交之所以能崩了再补完的原因.
- **改动只追加**(TODO 7.7):`append_delta` 把那几行写进 `<name>.log`,基表不动.
  提交记录里记着日志的条数,于是崩在半路的尾巴能截掉.
- **暂存名是在文件名后追加 `.new`,不是 `with_extension`**:表名可以带点
  (`study.movies.csv`),`with_extension` 会把它切成 `study.movies.new`.

### 格式是契约

- **模式 JSON 是磁盘契约**:`version`,字段名,`ty` 的 serde 表示都属于它.
  改名或改结构就是改文件格式.
- **新增字段一律 `#[serde(default)]`**,保证老文件仍然读得回来.已经有老文件在野外,
  它们的读回路径必须一直有效.
- **NULL 与转义是数据格式的一部分**:NULL 写成 `\N`,以 `\` 开头的文本写盘时多写
  一个 `\` 转义.**NULL / 空字符串 / 字面文本 `\N` 三者必须始终可区分**--动它就是
  动数据,先想清楚往返回来的还是不是同一个值.
- 写盘走**暂存 + rename**,不要直接覆盖目标文件(详见上面的"落盘分两步").

### 一致性

- `load` 必须**交叉校验** CSV 表头与模式文件的列名(含**顺序**),不一致就报
  `DbError::Format`.**绝不静默读出一张错位的表**--那比报错危险得多.
- 旁路方案的固有代价就是两份文件可能不同步.任何新的一致性检查都要以"宁可报错"为准.
- 模式文件里的 `name` 是表的**逻辑名**;文件主干名只用来定位.

### 验证

- 改这一层时,往返回来的**必须逐值相等**,包括 NULL 与含反斜杠的文本.测试里要拿
  这三者一起过一遍,不能只测普通字符串.
